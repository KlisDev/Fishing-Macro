    01 / All platforms

    Download the complete project

    1. Open the official repository

      Go to KlisDev/Fishing-Macro. On the main file list, choose Code → Download ZIP. Do not download a single Python file.

    2. Extract the ZIP

      On Windows, right-click it and choose Extract All…. WinRAR showing an archive does not mean it is extracted. On Linux, use your archive manager. Open the extracted folder, not the archive preview.

    3. Keep these files and folders together

      Fishing-Macro-master/       (the folder name may differ)
├── GUIDE.html
├── README.md
├── WINDOWS/
│   ├── easy_run.py
│   ├── run.py
│   ├── _bootstrap.py
│   ├── requirements.txt
│   └── bloxfish/
└── LINUX/

      Linux also needs WINDOWS/. It contains the shared fishing engine. Moving only a launcher into another folder breaks its imports.

    Next: Windows or Linux/Sober. For other devices, see platform support.

    02 / Windows 10 & 11

    Install & launch on Windows

    Main supported platform

    1. Install desktop Python

      The project requires Python 3.10+ and recommends 3.12 for dependency compatibility. Use a full installer from python.org, with pip and Tcl/Tk. For the traditional installer, tick Add python.exe to PATH. An embeddable ZIP or source archive is not the desktop installer.

      Already have Python? Keep it if it meets these requirements and installs the packages successfully. Very new Python versions may lack compatible prebuilt libraries. The latest maintenance release is not always offered as a Windows installer; check which release actually provides one.

    2. Open PowerShell in the extracted project folder

      Open the folder containing GUIDE.html and WINDOWS. In File Explorer’s address bar, type powershell and press Enter. Run:

      python --version
python .\WINDOWS\easy_run.py

      If Windows cannot find python but the Python launcher works, use py -3.12 .\WINDOWS\easy_run.py for an installed 3.12 version. This command does not install Python.

    3. Let the first dependency installation finish

      The Windows launcher installs the required Python libraries using that interpreter. Keep the terminal open. Once Python file associations work, you may also double-click WINDOWS/easy_run.py. Use the terminal if it opens an editor or closes immediately.

    4. Match Roblox’s permission level

      If Roblox runs as administrator and the macro does not, Windows can block its clicks and keys. Open PowerShell as administrator, change to your extracted WINDOWS folder, and run python easy_run.py. A correct F8 click marker shows the intended target, but cannot prove the game received the click.

    Ready: the setup window opens with the current version. Opening the app alone does not start fishing. Continue with Prepare & start.
    Missing libraries or dependency installation failed?

    From the project root, use the same Python that launches the macro:

    python -m pip install -r .\WINDOWS\requirements.txt
python .\WINDOWS\easy_run.py

    Keep the complete error if this fails. A network error, incompatible Python version, and missing compiler are different problems. Installing with another Python’s pip can leave the launch interpreter without packages.

    03 / Linux

    Linux with Sober & X11

    Experimental · live Sober confirmation still needed

    The Linux adapter uses the same current engine and GUI as Windows. It has separate calibration and diagnostics. Keep both platform folders.

    1. Use an X11 desktop session

      echo "$XDG_SESSION_TYPE"

      It must show x11. Wayland is unsupported, including Sober through XWayland. If needed, save your work, log out, and select an available X11/Xorg session at login.

    2. Install Python, Tk, and the Linux requirements

      On Ubuntu/Debian/Linux Mint, install the system prerequisites, including tools needed if evdev must build from source:

      sudo apt install python3 python3-pip python3-venv python3-tk python3-dev gcc libgl1 libglib2.0-0 libxrandr2

      Other distributions use their own package names. Check python3 --version; the shared code needs 3.10+. Use your distribution’s supported installation process if its Python is older. Open a terminal in the project root and make a virtual environment, which avoids installing packages into system Python:

      python3 -m venv .venv-linux
source .venv-linux/bin/activate
python3 -m pip install -r LINUX/requirements-linux.txt

    3. Allow virtual input once

      sudo bash LINUX/install-udev.sh

      This installs the supplied uinput access rule, loads the module, and adds your user to the input group. Review the readable script if needed. Log out and back in before continuing. Run the macro itself as your normal user, without sudo.

    4. Open Roblox through Sober

      Install and configure Sober using its official instructions. Open Blox Fruits and leave the game visible. The macro checks X11, virtual input access, the Sober window, and capture before starting the GUI.

    5. Launch from the project root

      In each new terminal, activate the environment first:

      source .venv-linux/bin/activate
python3 LINUX/easy_run_linux.py

      Calibrate on Sober itself. Windows settings do not substitute for Linux calibration. Continue with Prepare & start.

    More detail: Linux README. The F8 overlay uses X11 Shape; if visible hitboxes are unavailable, the diagnostic log can still work.

    04 / First successful run

    Choose your fishing mode

    Automatic Fisherman route

    Select Fisherman, enter your actual starting bait count to enable restocking, and choose a purchase amount. Selling is optional. Start at the NPC’s outer interaction edge, on a straight centre line.

    The macro manages Shift Lock and confirms the NPC menu before fishing.

    Fish-only, anywhere suitable

    Select Don’t buy. Buying and selling are both off, even with a saved sell interval. Choose your spot, aim, and Shift Lock state yourself. Prepare bait manually.

    No NPC anchor, movement, menu recovery, or automatic Shift Lock check runs in this mode.

    Setup fieldWhat to enter
    Bait per purchaseThe amount bought per trip, not what you currently own. The GUI offers 10 to 90 in steps of 10.
    Bait you have right nowYour real starting stock for this session. Blank disables automatic restocking. It is an estimate, not an inventory scan.
    Rod hotbar slotThe actual key for your rod: 1 to 9, or 0. Start with that rod equipped.
    Sell every N catches0 disables selling. Use a positive interval only if you want automatic Fisherman sales.
    Slower fish trickUse if the quick rod flick leaves a glitched fish in your hand.
    Faster bite reactionUses more CPU and can react to false markers. Leave off while diagnosing unstable detection.

    Before F2 on an NPC route

    • Roblox is visible, focused, and unobstructed, in the same window mode used for calibration.
    • Stand at the Fisherman’s outer interaction edge with Interact visible. Align your position and camera straight through the NPC centre, not diagonally.
    • Turn auto-run/running off. Enable Roblox’s Shift Lock Switch setting, but leave the current lock off.
    • Close menus manually, equip the rod, and select the bait you intend to use. Confirm the rod slot and actual bait count.
    • Use a plain avatar. Keep red/pink cosmetics, glowing effects, and aura particles out of the bite marker region.
    • Finish calibration and the in-app Preparation Guide. In Run Console, press F2 once or click Start.

    The initial Interact → Nevermind sequence establishes the pushed fishing position. It is expected even when you already have bait. Do not touch the camera, mouse, hotbar, or menus during the run.

    F2Start / PauseStart / Stop
    F4Stop current run; app stays openQuit
    F8Hitboxes and diagnostic log, when overlay is availableDiagnostic log only

    Test several catches and a complete restock or sale before leaving it unattended. After stopping, restore the checklist before a fresh start.

    06 / The deeper explanation

    Why the setup matters

    What the macro actually sees and does
    Charge & cast→Pink bite marker→Reel track & fish→Catch evidence→Rod flick / next cast

    It reads visible screen pixels and sends mouse/keyboard input. It does not read Roblox inventory or world coordinates, inject game code, or modify Roblox memory. Regions tell it where to look; colour and shape detectors tell it what appears there.

    The reel zone has momentum. Holding and releasing changes its motion, so the controller estimates movement and rod acceleration while reeling instead of merely copying the fish position. A little rapid correction can be normal. Repeated losses or a zone stuck at one end need diagnostics.

    How Shift Lock is verified, and why the icon is not enough

    For an NPC route, the macro assumes you start with active lock off. It frees the cursor for dialogue, then presses Left Shift for fishing. Verification checks whether the operating system cursor moves from away from centre to the actual game window centre, within a tolerance. It does not read the Shift Lock icon or a Roblox setting value.

    A lock that looks enabled can still fail that check if focus, input permissions, cursor queries, or window geometry are wrong. The current expected centre is independent of the saved Interact point. Failed verification stops the NPC route rather than casting with an unconfirmed cursor state.

    Why a tiny diagonal offset can grow on later shop visits

    Take a top-down view of the NPC’s interaction circle. Roblox pushes the player outward along a radial line, which can change both X and Z. The macro’s backward movement follows one direction and cannot independently correct the leftover sideways offset. Moving farther inward before dialogue can produce a longer outward push.

    With an off-centre start, each inward step followed by a radial push can increase the angle. It is not a fixed 0.1° added per visit. This is why the guide asks for a straight 0° lane and why the current route tries Interact without movement first, then at most two short S probes. It adds no fixed W correction after the push.

    A starting angle alone cannot give a reliable number of trips until failure. You also need movement distance, push geometry, changing camera direction, and the usable interaction boundary. The in-app position animation is an illustration, not a measurement of those values.

    How it decides to restock bait

    You enter the starting bait amount. The engine subtracts one when it registers a bite, including a fish that escapes, and attempts a purchase between catches when its estimate is at or below 1. It targets 1 instead of 0 because running out can unequip bait in Roblox.

    This is software bookkeeping, not OCR or a live inventory scan. False/missed bites, manual fishing, manual purchases, and bait conservation can make the estimate differ from the game. A purchase requires a visible Craft button before the confirmation click and its sustained disappearance afterward. Confirmed purchases are credited once, even if leaving the following menu fails. The macro does not independently read back every item in inventory.

    The route buys Basic Bait. There is no general automatic bait-equipping step after stock reaches zero. Start with bait selected and an accurate count. A blank count, Don’t buy mode, or repeated purchase failures disables restocking.

    For code-level detail and measured detector history, read MECHANICS.md. Some sections describe earlier failures rather than instructions for the current release.

    07 / Answers from the video questions

    Questions & fixes

    Choose the symptom you actually see. If a suggested check is already correct, collect evidence rather than repeatedly recalibrating everything.

    No matching questions. Clear the search or choose All questions. You can also report the problem with F8 enabled.

    easy_run.py opens briefly, closes, or shows code instead of the app

    Run it from PowerShell so the error stays visible. From the extracted project root:

    python .\WINDOWS\easy_run.py

    Opening code in an editor is a file association problem. An immediate exit can be a Python/import/install error. These need different fixes, so keep the exact terminal output. Check Windows installation instead of repeatedly double-clicking.

    It cannot find _bootstrap.py / “No module named _bootstrap”

    Keep _bootstrap.py beside WINDOWS/easy_run.py and run.py. Its name includes the first t: _bootstrap. Download and extract the full official ZIP; do not copy only the launcher.

    If the file is missing after extraction, inspect download/security alerts and quarantine history. Do not assume the warning is harmless or disable protection. Include the exact missing-file error if the complete folder still fails.

    numpy, cv2, mss, or another library is missing

    The Windows launchers try to install requirements automatically. If installation failed, use the explicit same-interpreter install commands. Linux needs its separate requirements and system Tk installation.

    Keep the pip error. Make sure python -m pip uses the interpreter that runs the macro. A newer Python with missing package wheels can require a compatible Python version.

    Which Python do I need? I already have Python installed

    Minimum: 3.10. Recommended in this project: 3.12. A working compatible installation does not need reinstalling just because the video shows another installer. Check python --version, pip, and Tk.

    Python’s newest release and the newest downloadable Windows installer may differ. Use official full installers. If a traditional installer has a PATH checkbox, enable it. If the newer install manager uses a different flow, follow Python’s Windows documentation.

    I downloaded a ZIP, but cannot find easy_run.py

    Extract the entire archive first. Then open the project’s WINDOWS folder. The launch file is there, not at the top level. A WinRAR icon simply identifies which program opens ZIPs. Follow the expected folder layout.

    How do I run it as administrator, and when does that matter?

    Find PowerShell or Windows Terminal in Start, right-click, choose Run as administrator, navigate to the extracted WINDOWS folder, and run python easy_run.py.

    Windows can reject input when Roblox is elevated above the macro. Matching that permission level can solve ignored clicks, unresponsive hotkeys, and a reel zone drifting despite correct detection. It does not repair wrong calibration or prove every click was delivered. Linux uses uinput permissions instead; do not run its macro as root.

    Roblox is open, but the macro cannot find it or captures the whole desktop

    Keep the actual game client open, visible, and not minimised. Check the configured window title and platform launcher. Bring the game forward, then Re-shoot. Do not save calibration while the tool warns that it captured your whole screen instead of Roblox.

    On Sober, inspect preflight warnings and confirm the live calibration image really shows the game. A black capture can be a capture issue or a legitimate dark scene; the image and diagnostic evidence determine which.

    The calibration screenshot or reference is too small to see

    Use the current build’s Zoom screenshot or Zoom reference. Scroll to magnify and drag to pan. The calibrator also resizes and scrolls its instructions.

    Close the zoom viewer before editing points or sampling colours. It is read-only. If boxes still display or save at half the real width, record the main workspace, reopen it after Save, and include resolution and display scaling in a bug report.

    What is the Re-shoot key? How do I capture a special UI in fullscreen?

    Re-shoot is an on-screen button, with no dedicated hotkey. Open the required game UI, bring the calibrator forward, then press it. The macro windows hide briefly for the screenshot. For a reel, arrange the live bar before capturing; advanced samples are optional.

    Keep the game in the mode you will use for fishing. Do not calibrate windowed and then switch to fullscreen. See the calibration workflow.

    I cannot move the calibration boxes or dots

    Select the corresponding item in the left-hand list first. Other controls are deliberately locked. Drag inside the selected area to move it; drag its white corner to resize it. A selected click point moves by dragging its dot.

    If you are in a zoom inspector, close it and edit in the main workspace. Record the selected item and mouse action if the current main workspace still ignores dragging.

    Calibration or settings disappear after closing the app

    Click Save calibration and read its status, including any write error. Setup also needs its save/continue action. Re-shoot alone is not Save. Reopen the same extracted project copy; another downloaded copy has a different config.json.

    Windows stores its profile in WINDOWS/config.json; Linux uses LINUX/config.json. The current bait count is a session input, so a blank bait field on a new setup is not lost calibration.

    Do I have to capture every advanced colour or fish template?

    No. Begin with normal regions and defaults. Optional samples help when your screen differs because of lighting, rendering, semi-transparent UI, or effects. Screens that appear similar can still produce different pixel values.

    If normal tracking works, extra samples are unnecessary. If it fails, sample the plain target rather than text or glow. Avoid copying another person’s colours or entire config without checking them on your own game.

    Do I recalibrate every launch? Which aspect ratio should I use?

    Calibration persists. Repeat it after changes to window size, fullscreen mode, display scaling, resolution, or Roblox UI layout. There is no one required aspect ratio; use a stable layout that your PC runs smoothly and calibrate that exact layout.

    Another person’s setup is an example, not a guaranteed preset for your display.

    Shift Lock turns on, but it says it did not engage

    On NPC routes, the macro verifies the OS cursor snapping to the actual game-window centre. Watching the icon turn on does not prove that test passed.

    1. Check your version and update older builds.
    2. Enable Roblox’s Shift Lock Switch, leave active lock off, and move the unlocked cursor away from centre before F2.
    3. Keep Roblox focused, visible, and at the same permission level as the macro.
    4. If it still fails, include the before/after cursor positions, expected centre, and tolerance from the log with an F8 video and issue.

    Do not bypass verification or tell the program to assume lock succeeded. Fish-only mode intentionally skips this check; see its separate preparation.

    Should I change shop.center to 0.5107 to fix Shift Lock?

    No. That was a workaround for an older check tied to the Interact calibration point. Current verification uses the actual game-window centre independently.

    Put Interact on the real prompt. If you used the old workaround, recalibrate that point. Do not force every screen to another person’s Y coordinate.

    “NPC anchor failed”, or it opens the Fisherman menu and stops

    The macro could not establish a confirmed root menu for the startup route. This happens before fishing begins; it is not a Python installation diagnosis.

    Check the earliest preceding log line. No dialogue points toward reach, Interact, focus, or input. Visible dialogue with unconfirmed rows points toward menu detection or region coverage. A confirmed menu that will not close points toward the exit click or input acceptance.

    Start on the outer interaction edge with Interact visible, aligned through the NPC centre. Verify the full menu area and actual click point. If those already match, report the failing stage with F8 rather than repeating all calibration.

    Dialogue is visible, but “root rows are not confirmed”

    The root page needs four complete rows: Shop, Fishing Index, Job Stats, Nevermind. The menu search area must include all four and the lower two-row bait page, while excluding unrelated HUD or console text.

    The macro refuses to move while a menu appears open but its page is uncertain. This protects the position. An extra/missing action after a game UI update can require a detector/page-map update; it cannot always be fixed by moving dots.

    F8 shows the correct button, but Roblox ignores the click

    The dot marks where the macro attempted to click. Confirm permission level, game focus, and that dialogue Shift Lock is actually off. Update older builds: .44 verifies Windows F8 click-through and keeps log-only diagnostics if a safe overlay cannot be established.

    If the correct Nevermind target still does nothing, add the F8 recording and diagnostic log to an issue. This needs input and state evidence; correct target detection alone does not prove the game accepted the click.

    Why talk to the NPC at startup when I already have bait?

    That interaction anchors the fishing position using Roblox’s outward push. The macro closes the confirmed root menu, enables verified Shift Lock, and starts fishing. It does not buy bait unless the restock condition is met.

    No forward W walk is expected in this build. If it stops after Nevermind, read whether the failure is dialogue closure, Shift Lock verification, or casting.

    How do I align at 0°, and how fast can misalignment stack?

    Use a straight line through the NPC’s centre and your character, with the camera aligned on that same lane. Stand directly in front of or behind the NPC at the outer interaction edge. Do not approach from a diagonal just because Interact is visible.

    A slight lateral offset can grow when a fixed-direction inward step is followed by the NPC’s diagonal radial push. Deeper entry can increase the push distance. A starting 0.1° does not determine a fixed number of buy/sell trips. See the geometry explanation.

    Does it work in First or Second Sea? I fall into the water

    The macro uses the Fisherman UI and your screen calibration, not a navigation route for a specific island. Dock space and the interaction edge can make positioning harder in some locations. Choose an edge that allows the NPC push to leave you on solid ground facing water.

    Turn running off and avoid a diagonal approach. It does not pathfind around the dock or automatically change S to A/D for each sea. If you cannot prepare a stable NPC position, fish-only mode is an available option with manual resources.

    It opens Fishing Index, or menu buttons move between pages

    The current route confirms the visible page and finds its live action stack before clicking. The same row number can mean different things:

    PageRows from top to bottom
    RootShop · Fishing Index · Job Stats · Nevermind
    ShopBuy Bait · Sell Fish · Nevermind
    BaitBasic Bait · Back
    SaleConfirm · Nevermind

    Check your version and the full menu envelope. If your actual page has additional rows or different actions, report that complete page with F8. The current map cannot safely infer an arbitrary new menu.

    It needs two exit clicks after buying bait, but only clicks once

    The intended exit is Back from the bait page, then Nevermind from Shop. These are two page transitions, not one fixed click location.

    Current routing checks the page between actions. If it leaves the second page open, include an F8 video through both transitions and the full shop log. Do not add a blind extra click, which can land in the game after a menu already closes.

    “No charge”, “meter peaked at 0”, or it holds the rod without casting

    Confirm the rod is equipped and its configured hotbar slot is correct. The charge-meter region must cover the meter as your character moves; make it broad and central. Keep menus closed and the game unobstructed.

    If the meter never appears, check input/focus and whether the centre click is reopening the NPC. If it appears but F8 does not detect it, inspect region coverage and colours. Record a complete cast attempt, not only the final retry message.

    It hooks at nothing, ignores bites, or repeatedly recasts

    The bite detector looks for a pink marker above your character. Red/pink hats, crowns, fruit auras, particles, and player-list text inside that region can trigger it; bright scenery can hide the real marker.

    Use a plain avatar and remove interfering visual effects. Resize the bite region around the real marker without reaching the player list. Compatibility depends on what is visible, so a race or fruit name alone cannot guarantee failure or success.

    The reel zone slides left/right and stops following the fish

    First separate ignored steering from wrong detection. Check Windows input permission level, or Linux uinput access. Then use F8 to see whether the macro identifies the real full track and fish.

    Crop the reel band around the full UI with a margin, excluding health/energy/mastery bars. Keep the progress strip. A cut-off track gives the controller the wrong width. If needed, use a properly drawn optional zone-track box or actual colour samples.

    Reduce visual interference, keep the camera steady, and test a darker scene if daytime glare is a factor. If the same failure persists, record one full reel with F8; do not assume another calibration reset will solve it.

    F8 outlines only part of the reel bar, even with a large enough search area

    Update to 1.8.2.1. During the opening fade, the old detector could measure only the bright filled section of the progress strip and keep that short width for the fight. The correction also measures the dim remainder and protects detection areas from nested F8 graphics.

    Keep both ends of the track and the thin progress strip inside the calibrated area, with a small margin. This fix cannot recover pixels outside your box. Color samples are not required just to use the fix.

    The supplied recording passes the full-width replay checks at 4K and 1080p. That confirms the reproduced case, not every possible live setup. See the issue #53 evidence; report a remaining failure with one complete reel and F8 enabled.

    “Zone hidden (chest/alarm)” repeats, but no chest is visible

    That message means the zone detector could not read the zone while other evidence still showed a live reel bar. “Chest/alarm” describes possible reasons, not a confirmed chest or alarm on screen.

    Inspect the reel crop, lighting, zone colour, and the optional zone-track box, including its progress strip. A false bar witness can also keep it waiting. An F8 video plus log and, ideally, --dev captures are needed to distinguish those cases.

    The reeling looks jittery, overshoots, or struggles with a small zone

    The zone has momentum and the controller alternates hold/release, so visible corrections are expected. Check catch results rather than judging movement alone. Repeated fish loss is a real problem.

    Make sure the full track width is correct. The optional zone-track box can reduce scenery and width errors. Fast rods and darting fish are harder; the controller learns rod movement during use but does not guarantee every catch.

    It recasts or flicks the rod while the fish is still being reeled

    A live bar should prevent another cast. Earlier builds had premature end-detection failures. Update first, then confirm the reel crop includes the progress strip and F8 is reading the actual track.

    If the bar is visibly live when the reset happens, record from the bite through the reset with the log. That is different from an intentional flick after a confirmed catch.

    The rod flicks and skips the catch notification. Did I lose the fish?

    The quick rod flick is intentional after catch confirmation. It stows and redraws the rod to skip the normal catch card and help clear a stuck game state. A missing catch card alone does not prove lost rewards.

    If it leaves a glitched fish in your hand, enable Slower fish trick. If actual inventory or rewards fail to change, record those before/after values and the F8 log; that needs evidence beyond the animation.

    It misses treasure chests or loses the fish while reaching one

    Chest detection can differ with the tile’s colour on your display. In Advanced colours, sample the Treasure chest tile. Confirm with F8 whether a chest was actually detected.

    Reaching a distant chest takes time and can let a hard fish escape. A failure after collecting a chest needs a full reel recording and diagnostic captures. Chest collection is attempted, not guaranteed.

    It fishes correctly, but never buys more bait

    Choose Fisherman and enter the actual stock in Bait you have right now. A blank count disables buying. Select a positive purchase amount. Verify the Run Profile says automatic buying is on.

    The default restock threshold is an estimated 1 bait, between fishing attempts. It does not scan inventory. If the log reaches that threshold but the route fails, inspect the NPC position, menu, and Craft stages. After repeated failed purchases, it disables restocking for that session.

    Restocking stops on Basic Bait / Back, or says the Craft window did not close

    Update to 1.8.2.1. The detector now distinguishes the Craft button from the yellow Fisherman name banner and keeps highlighted NPC rows detectable. Page transitions also allow a bounded settling interval after rendering. The required action counts remain 4 for Root, 3 for Shop, and 2 for Bait; they are not bypassed.

    1. Keep your existing calibration. Check that the menu area covers the complete action stack on each page and that the Craft region contains the real yellow button.
    2. Test a complete restock while watching. It should confirm Craft, then click Back → Nevermind before returning to fishing.
    3. If it stops, keep the earliest failure, observed row counts, and stable-time diagnostic. A later bait-page error can come from recovery, not the original failure. Do not manually click through while the macro is still running.

    Recorded-image and simulated routes pass, but issue #55 has no reporter captures or config yet. Its exact intermittent failure and camera turning are not live-confirmed as resolved. If they persist, attach your config, the F8 log, and the stuck page or development captures. Do not reset everything or add blind exit clicks. See the investigation and limits.

    It uses all bait, buys more, but needs me to equip it again

    Start with bait selected and an accurate current count. The route tries to buy before zero because Roblox can unequip exhausted bait. It has no general auto-equip bait action after that happens.

    If it reaches zero early or buys the wrong amount, capture the counter, purchase sequence, and any “equip bait” prompt. Stop, select bait manually, correct the session count, and prepare again. The counter explanation covers why estimates can drift.

    What is the difference between purchase amount and starting bait?

    Purchase amount is how many Basic Bait to buy per trip, in multiples of ten. Starting bait is how much you actually have now and need not be a multiple of ten.

    For example, if you own 23 and want 20 per purchase, enter 23 as current stock and 20 as purchase amount. Do not deliberately understate stock as a universal fix; it makes the software estimate inaccurate.

    Does the macro read my real bait inventory?

    No. It subtracts one per detected bite, including misses, and credits the requested purchase after route success. Conservation, false markers, missed markers, or manual actions can break the match to real stock.

    Re-enter the actual amount for a new setup session. Monitor a complete purchase when diagnosing counters; “topped up” is not an independent inventory readback.

    It clicks Learn in the Craft window, misses +/Craft, or presses Close

    Check the special-UI calibrations separately: recipe Learn/popup detection and the bait Craft button region. They can overlap or resemble one another if calibrated against the wrong page.

    Re-shoot with the Craft window actually open and unobstructed. Place +, Craft, and Close on the corresponding controls. Close can be a recovery action after an earlier stage fails; read the preceding shop log. If it still mistakes Craft for Learn, send an F8 video showing both the selected regions and failure.

    I request 30 or 90 bait, but it only buys 10

    The Craft window starts at 10; each + should add another 10. The route calculates the required presses but does not OCR every resulting quantity. Slow UI responses or rejected clicks can leave the displayed amount lower than requested.

    Record the actual quantity and + clicks with F8. Confirm focus and calibration first. Only adjust relevant cooldowns from observed missed transitions; arbitrary global delays can hide the cause.

    During restocking it keeps equipping the fishing rod

    Stowing before an NPC route and re-equipping afterward is intentional. Repeated cycling without completing the route is not a successful purchase. Verify the selected slot contains only the rod and start with it equipped.

    Do not manually change hotbar state during the run. Include the final reel, first NPC interaction, and failed purchase in an F8 recording so the actual route failure is visible.

    Why does it not always walk backward to buy bait?

    The current route first tries Interact from the position Roblox left it in. It sends at most two short S probes only when dialogue is absent. An already-visible menu prevents further movement.

    No movement can therefore be correct. If Interact cannot reach the NPC and probes do not open a confirmed menu, collect that route log and F8 video. It does not automatically navigate toward a distant Fisherman.

    How do I stop selling fish or protect rare catches?

    Set Sell every N catches to 0 to disable automatic sales. Don’t buy mode disables both buying and selling. There is no species/rarity filter in the macro.

    The NPC sale behaviour described by the project preserves favourited fish and your heaviest. If a fish matters to you, keep selling off until you verify the game’s current sale confirmation yourself. Do not assume “mythical” alone prevents sale.

    Does it buy Epic bait, craft Levi bait, or handle new bait types?

    The automatic purchase route is mapped to Basic Bait. It does not select arbitrary bait types or craft special ingredients. The fishing loop can attempt a normal visible minigame with your prepared resources, but that does not add a special purchase route.

    For a changed menu or new bait page, report the entire UI. Do not move the Basic Bait dot onto another item and assume the rest of the route will match.

    “Shop disabled for this run”, or it gives up buying after failures

    Check mode and starting count first. Buying is off with Don’t buy, a blank stock count, a non-positive purchase amount, or when the purchase-failure limit is reached. The default limit is three failed attempts.

    Correct the underlying route problem before restarting. Repeated restarts without fixing the failed stage can keep consuming the remaining bait.

    It says Stopping, or pressing F2 logs an F4/Stop request

    F2 toggles the running state. The shared stop path can log “requested by F4 / Stop control” even when a start/pause action ended up stopping a run; that text alone does not prove the keyboard sent F4.

    Press once and wait for Idle before starting again. Try the on-screen Start control if a global key is missing. A current build that remains stuck in Stopping needs a report showing start, stop, and failed restart with F8 enabled. Relaunching is a temporary recovery, not a diagnosis.

    F2, F4, or F8 does nothing

    Check whether your laptop requires Fn + function key or a function-lock change. On Windows, also check input permission level. Use the GUI Start/Stop buttons as a fallback for starting and stopping.

    A missing keyboard shortcut is different from an engine stuck after stopping. If both the key and button fail, show the Run Console state. If F8 cannot be enabled, say so and include the visible log in your report.

    What does “turn off auto-run” mean?

    It means the game’s running/sprint state, not automatic fishing or the Python launcher. Switch running off using your current game controls, then confirm the character walks at normal speed before preparing the NPC position.

    The macro uses short timed movement probes; running can make them travel farther than intended and push you too deep into NPC range or off a dock. Keep it off for the whole run.

    It runs for a while, then suddenly stops

    The default watchdog stops and releases held input after five minutes without a confirmed game response. An attempted cast or click alone does not reset it. A visible Safety Stopped message is an intentional stop, not proof of a crash.

    If stopping lines up with the first bait or sell trip, inspect that route first. Otherwise check focus, missing detection, disconnects, and the last confirmed response. The catch count alone cannot identify the cause.

    F8 writes a log but I cannot see hitboxes

    The GUI supports the overlay; terminal run.py writes diagnostics only. An overlay that cannot confirm native click-through on Windows is suppressed while logging stays available. Linux needs X11 Shape for visible hitboxes.

    In 1.8.2.1, Windows overlay graphics inside any active detection rectangle are cleared, including nested frames and markers, so they do not alter captured pixels. Missing graphics inside those protected areas can be intentional; consult the diagnostic log too.

    Check the debug message rather than assuming F8 did nothing. Report it with the log if you expected GUI hitboxes but the overlay was unavailable.

    Can I watch something else or use the PC while it runs?

    The macro needs Roblox visible and focused, and it controls your mouse/keyboard. Merely putting another video on a second monitor does not guarantee trouble-free operation: clicking it can steal focus, and other inputs can change the camera or hotbar.

    Minimising Roblox, covering the UI, locking the desktop, or letting the PC sleep is unsuitable. Stop before actively using other apps.

    The camera changes, or it casts onto land after a shop trip

    Check the initial straight NPC alignment, auto-run state, and whether Shift Lock was verified after dialogue. The NPC’s own push can change position and camera; manual mouse input or game effects can disturb it too.

    If camera shake is available in the game settings, disabling it may reduce disruption. The macro does not reconstruct a world-space fishing direction. Record the last good cast through the camera change with F8.

    Can I fish anywhere and skip the NPC entirely?

    Yes. Select Don’t buy. It disables automatic buying and selling, NPC anchoring/movement/dialogue recovery, and automatic Shift Lock toggles/checks. Blank bait tracking plus selling set to 0 also produces fish-only behaviour.

    Choose a suitable spot outside NPC range, close menus, equip the rod and bait, and prepare your aim and cursor/Shift Lock state yourself. Detectors, rod flick, chest handling, and the watchdog remain active. A persistent recipe Learn note stops this mode so you can clear it manually.

    Windows, Linux, Mac, mobile, or Chromebook: what is supported?

    Windows 10/11 is the main platform. Linux/Sober on X11 has an experimental adapter in this project. Wayland is unsupported.

    This repository has no maintained macOS or mobile launcher. A community Mac fork is linked from the videos; its compatibility and maintenance are separate and unverified here. ChromeOS is not a supported platform, and enabling a Chromebook Linux container does not establish Sober/X11/input compatibility.

    The existing PC guide cannot be followed directly on an Android phone or iPhone.

    Linux launch fails or reports missing uinput/X11

    Follow the Linux steps. Use a real X11 session, install system Tk, activate the virtual environment, install Linux requirements, and run the supplied udev installer once followed by logout/login. Open Sober before launching.

    Do not use sudo for the macro, pretend Wayland is X11 by changing variables, or bypass failed input checks. On an “externally managed environment” pip error, use the virtual environment rather than overriding system protection.

    What are the lowest PC specifications, and how much RAM does it use?

    No measured minimum or fixed RAM requirement is published for this macro. Any exact CPU/RAM claim would be an estimate. You need a supported desktop, compatible Python, and enough resources to run Roblox smoothly alongside capture and image processing.

    Measure your own total Roblox + Python load in Task Manager or a Linux system monitor during a reel. Resolution affects capture size; fast bite reaction increases CPU use. Future OCR/Angler RAM costs cannot be stated accurately before implementation and measurement.

    Does it complete Angler quests or automatically understand tasks?

    No. Current automatic NPC routes are for the Fisherman. There is no Angler quest OCR, task planner, island navigation, or general combat/mastery farming.

    Supporting quests would require reading the objective and safely handling each supported task, not merely clicking an accept button. Feature requests are welcome, but this guide does not promise a release date or memory cost.

    Will catching a fruit replace my current fruit or make the macro eat it?

    Catching a fruit does not automatically put it in your hand and replace your equipped fruit. However, do not manually equip a fruit while the macro is active. Its dialogue can be confused with another popup, and automatic clicks may hit the wrong action.

    Stop the macro before handling fruits or inventory. Automatic recipe-note handling is not general understanding of every game dialogue.

    Does it open collected chests or bypass daily reward limits?

    It attempts to collect the chest tile during reeling. It does not automatically open stored chests, choose a chest reward type, or bypass the game’s inventory/daily limits.

    Old comments disagree on reward caps. This guide does not treat those numbers as verified current rules. Check the game’s current UI or official update information. Fruit and chest rewards are random; no fixed hourly return is guaranteed.

    Is this a macro or an exploit? Can I still get banned?

    It is a desktop program that reads screen pixels and sends normal mouse/keyboard input. It does not use an executor, inject Roblox code, or modify Roblox memory.

    Those technical differences do not guarantee permission under Roblox or Blox Fruits rules. Automation can still lead to enforcement, and a private server does not remove that risk. See Roblox’s cheating/exploiting guidance and the game’s current rules.

    My antivirus flags the download. Is it automatically a false positive?

    No. Capture and automated input can attract heuristic alerts, but that does not explain or clear your particular alert. Use the official repository, inspect the source and the exact warning, and investigate before allowing anything.

    This project supplies readable Python rather than a bundled Windows executable. Dependencies install separately. Open source helps inspection; it is not proof that any copy or dependency is harmless. Do not disable security protection just to launch it.

    Will it run overnight, catch rare fish, or keep me safe from players?

    It attempts whatever fish produces the normal supported reel minigame. Success varies with rod, fish movement, detection, input, lag, and resources. No fixed levels, money, fruits, or perfect catches per hour are guaranteed.

    There is no automatic reconnect, death recovery, combat defence, or travel back to the NPC. A private server may reduce interference but does not guarantee uptime or remove account-rule risk. Test your own catches and complete restock/sale before a long run.

    Do I need a specific rod or enchantment?

    The controller estimates zone motion to adapt to different rods, but that is not a guarantee for every special rod or game mechanic. Confirm the rod hotbar slot, use the normal reel layout, and test several catches.

    The macro does not activate arbitrary rod skills or exploit-specific speed tricks. An unusual mechanic needs its own diagnostic recording before compatibility can be claimed.

    Can I read the instructions in Russian or another language?

    Use your browser’s page-translation feature on this HTML guide, or translate selected text. Browser translation availability and offline language support vary. The code commands and file names should stay exactly as written.

    This does not translate the macro interface or add recognition of translated in-game action labels. Mention your Roblox language in a report if the UI text differs from the illustrated menu.

    1. Enable F8 before reproducing it

      Use the GUI launcher. F8 enables diagnostic logging and visible hitboxes/click points when the overlay is available. If F8 or the overlay fails, state that and keep the visible console output.

    2. Record the whole failure

      Show a little before the problem, the failed action, and the Run Console. For bait problems, include the last reel, menu path, displayed purchase quantity, and return to fishing. For restart problems, show the initial start, stop, and failed retry.

    09 / Keep a working setup

    Updates, settings & local files

    What changed in 1.8.2.1?
    • Reel width: detect the dim unfilled progress section instead of locking onto only the bright portion; prevent nested Windows F8 graphics from contaminating detection.
    • Bait restocking: separate Craft from the NPC name banner, retain hovered action rows, allow bounded page settling, and confirm a real Craft click before crediting bait.

    Both platforms use these shared detector and route fixes. Existing configs remain compatible; no reset or new mandatory color sample is needed. Recorded and simulated checks are not live Roblox or Sober certification.

    How do I update without losing calibration?
    1. Stop and close the macro. Back up your active config.json and optional fish_template.png.
    2. Download the complete official project again and extract it to a new folder.
    3. Restore the profile into the same platform folder only if the display/layout is unchanged. Profiles migrate supported user settings; do not mix old source files into new code.
    4. Launch the new copy, check its console version, and test calibration and one full NPC route if enabled.

    There is no automatic updater in the current launchers. Windows and Linux settings are separate. Recalibrate any control affected by an actual UI or display change.
